# Думающая система (brain-inspired)

Исследовательский проект: **думающая система, которая со временем всё лучше понимает материал и обучается по нему** — построенная на принципах мозга (brain-inspired), а **не** как обёртка над языковой моделью.

Принципы:
- Интеллект рождается из **архитектуры** (восприятие + память + предсказание + рассуждение + обучение во времени), а не из предобученной LLM.
- Накопление понимания — через **внешнюю структурированную память** (эпизодическая / семантическая / процедурная).
- Домен-агностичность; обучаемые нейрокомпоненты.

## MVP: предиктивный цикл (шаг 1 дорожной карты)

Замкнутый цикл **предсказание → ошибка → обучение** на одном потоке:

```
поток → энкодер → предиктор (следующий латент) → ошибка учит предиктор
      → опыт в эпизодическую память → replay дообучает предиктор
```

Запуск:

```bash
pip install -e .          # ядро (numpy)
python run_mvp.py         # демонстрация: ошибка предсказания падает со временем
python run_mvp.py --plot  # + PNG-график (нужен extras: pip install -e '.[viz]')
pytest                    # тесты (pip install -e '.[dev]')
```

На синтетическом потоке модель обходит тривиальный baseline (persistence) в
2.6–9 раз по финальной ошибке (медиана ×3.8 на 20 сидах) — измеримый признак
«понимание растёт со временем». (Цифра «ошибка падает ~99 %» тоже верна, но
слабее, чем звучит: почти весь спад — уход от случайной инициализации;
содержательная величина — отрыв от baseline.)

## Шаг 2: любопытство через активный вывод

Агент перестаёт быть пассивным — он САМ выбирает, какой канал наблюдать, чтобы
максимизировать прирост информации. Эпистемическая ценность канала — статистически
значимый **learning progress** (устойчивое падение ошибки); это прокси ожидаемой
свободной энергии в духе LP-любопытства (Oudeyer), а не полный EFE.

```bash
python run_step2.py             # любопытство vs случайное внимание, 5 сидов
python run_step2.py --seeds 10  # больше сидов
```

Среда — 4 канала разной выучиваемости (easy / medium / hard / noise). Скрипт
агрегирует по сидам (среднее ± σ + счётчики «на скольких сидах эффект есть»).
Честная картина по 5 сидам:

- **устойчиво (5/5 сидов)**: максимум внимания — на ещё-выучиваемом канале
  (hard 35.4±2.5 % против 24.8±0.4 % у random), ошибка на выучиваемых ниже random;
- **слабый эффект**: внимание на шум за весь прогон 21.8±2.0 % против 25.1±0.3 %
  у random — перманентного залипания на «шумном телевизоре» нет, но в ранней фазе
  любопытство тратит на шум *больше* random (пока учит его среднее);
- **не устойчиво**: аккуратный куррикулум easy→medium→hard виден лишь на части сидов.

> Примечание про `pymdp`: библиотека реализует точный дискретный POMDP-вариант
> ожидаемой свободной энергии. У нас модель мира непрерывная (латентная), поэтому
> active-inference выбор реализован нативно поверх неё, а `pymdp` оставлен швом
> для дискретной формулировки (см. `policies/active_inference.py`).

## Шаг 3: консолидация / непрерывное обучение без забывания

Доказываем, что система **не забывает** старое, обучаясь новому. Последовательность
из нескольких различных задач (режимов) предъявляется по очереди одной общей модели
мира. Сравниваем по образцу Complementary Learning Systems:

- **naive** — без повторения (память сбрасывается на каждой задаче) → катастрофическое забывание;
- **replay** — CLS-консолидация (эпизодическая память хранится между задачами и переигрывается) → забывания почти нет.

```bash
python run_step3.py   # матрица задача×задача + ACC / forgetting / BWT / FWT
```

Скрипт печатает три конфигурации рядом — это честная рамка:

```
метрика                    naive   replay-full   replay-ltd (буфер 500 = 3% опыта)
forgetting (рост ошибки)  0.38    -0.00          0.30
ACC (финальная ошибка)    0.29     0.005         0.24
```

replay-full хранит ВЕСЬ опыт (полный rehearsal) — потому и «обнуляет» забывание;
это верхняя граница, а не консолидация при дефиците памяти. Ограниченный буфер
помогает, но заметно слабее — честное текущее состояние. Метрики — по
Lopez-Paz & Ranzato (GEM, arXiv:1706.08840). Швы под развитие — generative
replay (синтез прошлого без хранения), reservoir-выборка буфера, EWC.

## Реальные данные: обучение по книгам (все языки + код)

Система читает книги из `books/` (PDF через PyMuPDF; Markdown/txt; файлы кода
`.py/.js/…`) и учится предсказывать следующую единицу текста — та же машинерия
предсказание→ошибка→память/replay. По умолчанию — **байтовый уровень (UTF-8,
фиксированный словарь 256)**: это УНИВЕРСАЛЬНОЕ представление, любой язык и любой
код кодируются одинаково, без языковой настройки. Честная метрика — **bits-per-byte
на отложенной (held-out) части** против тривиальных бейзлайнов.

```bash
pip install -e . && pip install pymupdf
python run_book.py                     # байтовый уровень (по умолчанию), книги из books/
python run_book.py --books mybook.pdf  # один файл; --level char — символы Unicode
```

Воспроизводимый из репозитория результат (образцы в `books/`, 14.6 КБ, held-out —
хвост корпуса, которого модель не видела; unigram обучается только на train):

| данные | метрика | uniform | unigram | МОДЕЛЬ |
|---|---|---|---|---|
| образцы `books/` (рус. учебные md) | bits/byte | 8.00 | 5.42 | **2.42** ✅ |

Модель **бьёт unigram на held-out** → выучила контекст, а не просто частоты.
Оговорки честности: корпус крошечный и шаблонный (часть n-грамм теста дословно
встречается в train), так что это работа с контекстом, но слабое свидетельство
обобщения; чекпоинт выбирается по тому же held-out (при отдельном val/test
результат сохраняется: 2.09 против 5.50).

> Числа на внешних данных — книга-PDF 156 КБ (bits/char 7.40/5.91/**4.25**) и
> смесь языков+кода 49 КБ (8.00/5.46/**4.91**) — получены на файлах, которых
> **нет в репозитории** (`books/*.pdf` в .gitignore из-за копирайта), и из репо
> невоспроизводимы.

## Единый контур и действие во внешнем мире

- **Единый когнитивный контур** (`run_agent.py`): один агент читает реальные тексты,
  сам выбирая источник (любопытство), предсказывает байты, по surprise находит
  аномалии и запоминает с консолидацией — учится 5.3→2.2 бит/байт; без консолидации
  забывает (BPC ×15 хуже); на лету находит опечатку в новом коде.
- **Действие в мире** (`run_world.py`): агент в незнакомом лабиринте строит модель
  мира и доходит до цели — 794 → 24 шага (оптимум), ~50× лучше случайного; held-out
  проверка — тот же механизм на 10 свежих случайных лабиринтах: 10/10, ×1.02 от
  оптимума (модель мира про-лабиринтная: в новом мире учится с нуля).
- **Обучаемая JEPA-модель мира** (`run_latent_world.py`): на зашумлённых наблюдениях
  учит инвариантные коды клеток и предсказывает последствие действия со 100% — основа
  планирования в непрерывных/шумных мирах (вместо таблицы).
- **Частичная наблюдаемость / POMDP** (`run_partial.py`): агент видит только локальный
  обзор, ведёт байесовскую веру, локализуется (14 гипотез → 1) и доходит до цели в
  100% против 57% у безпамятного.
- **Язык → цель → поведение** (`run_language.py`): цель задаётся словами и агент идёт
  к понятой цели. Честные числа: рекомбинации знакомых слов — 100 %, но по-настоящему
  невиданные фразы (held-out по фразам, слова вне словаря train) — 30 %: это
  bag-of-words на закрытом словаре, слепой к порядку слов и отрицанию, а не
  «понимание».
- **Объединённый агент** (`run_unified.py`): один агент действует в зашумлённом
  частично-наблюдаемом мире по языковой команде — обученное восприятие + байесовская
  вера + грунтинг языка вместе; восприятие 100%, навигация к языковой цели 8/8
  (команды из той же закрытой грамматики, что и обучение).
- **Иерархическая память** (`run_hierarchical.py`): эпизод → семантика (ориентиры по
  betweenness) → навыки (маршруты); 4 ориентира вместо 40 клеток, ~10 навыков на 60
  целей, план по ~2 ориентирам вместо ~5 шагов.
- **GPU/torch-бэкенд** (`run_torch.py`): torch-предикторы — drop-in замены numpy тем же
  интерфейсом (автоопределение CUDA); та же система масштабируется на GPU.

## Навыки, перенос, рассуждение (вторая половина проекта)

- **Q-опции / иерархический RL** (`run_qlearn.py`, `run_skills.py`, `run_latent_q.py`):
  навыки как политики (options) учатся из опыта Q-обучением, компонуются в цепочки;
  Q поверх выученного восприятия вместо таблицы.
- **Перенос навыка между мирами** (`run_transfer.py`): навык, обученный на одних
  лабиринтах, проверяется на 20 СВЕЖИХ из того же распределения — zero-shot 60 %
  против 5 % у необученного; few-shot тёплый старт. Единственный в проекте замер
  настоящего distribution shift — образец для остальных подсистем.
- **Открытие подцелей** (`run_option_discovery.py`, `run_spectral_options.py`):
  горлышки-подцели агент находит сам — по внутренней мотивации и из спектра графа
  переходов (eigenoptions).
- **Рассуждение** (`run_benchmark.py`, `run_causal.py`, `run_reasoning.py`,
  `run_research.py`): индукция программ из 2–3 примеров (10/10 на алгебре+Python,
  с честным показом провалов); причинность see/do/контрфакции (граф задан приором);
  замкнутый круг «вывод → гипотеза → проверка исполнением → пробел».
- **Рост языка операций** (`run_dsl.py`, `run_grid_growth.py`, `run_grow_solutions.py`):
  библиотека абстрагирует повторяющиеся комбо из найденных решений (DreamCoder-lite);
  выученные абстракции сериализуются (`LibraryLearner.save/load`).

## Реальный ARC-AGI-1 (воспроизводимо из репозитория)

`run_arc.py` меряет систему на настоящем ARC (Chollet) по честному протоколу:
программа ищется **только по train-парам** задачи, засчитывается только точное
совпадение на **скрытых test-входах**; рост библиотеки — из решений сплита
training, выигрыш меряется на непересекающемся сплите evaluation.

```bash
pip install -e '.[arc]'   # датасет ARC-AGI-1 приходит с пакетом arckit
python run_arc.py         # оба сплита + рост библиотеки (~15 мин)
```

Реальные числа (seed 37 общих примитивов, глубина 2, бюджет 4000):

| сплит | верно на скрытых test |
|---|---|
| training (400 задач) | **36 (9.0 %)** |
| evaluation (400 задач), seed | **5 (1.2 %)** |
| evaluation после роста библиотеки из training-решений | **7 (1.8 %)** |

Рост библиотеки даёт **+2 невиданные задачи**: абстракция `flip_h∘flip_v`,
выученная из training-решений, делает композицию глубины 3 достижимой на
глубине 2 (`flip_h∘flip_v ▸ mirror_quad`). Это настоящий перенос роста
языка между непересекающимися наборами задач; цена — поиск дороже (библиотека
шире). 8.2 % — честный масштаб текущего словаря, не SOTA.

Пятый слой seed — РАСШИРЕНИЕ (`reasoning/expansion.py`: upscale2/3, tile_h/v,
mirror_h/v — общая алгебра смены размера) — дал +11 задач training
(25 → 36 в богатой конфигурации: «upscale2», «mirror_v», «bbox ▸ tile_h»,
«top_color ▸ upscale3», …). Прежний seed почти целиком сохранял размер сетки —
самые частые мотивы ARC («клетка → блок», «сетка + зеркало») были невыразимы
ни на какой глубине; это был честно измеренный предел языка.

ВЫЧИСЛЯЕМЫЕ аргументы — следующий уровень переменной-цвета: `keep[top]` /
`drop[rare]` / `paint[top]` связывают цвет не перебором палитры, а функцией
от самого входа (top — самый частый цвет, rare — самый редкий). Одна программа
работает на train-парах с РАЗНЫМИ палитрами — перечисляемый `paint[c]` такого
обобщения дать не может в принципе. Замер: training 44 → **48 (12.0 %)**
(«keep[rare] ▸ bbox» — «вырежи объект самого редкого цвета», ×2;
«keep[top] ▸ bbox»; «paint[rare] ▸ keep_largest»).

Шестой слой — ОТНОШЕНИЯ (`reasoning/pairwise.py`: and/or/xor/diff над
половинами сетки, при нечётном размере средний ряд/столбец-разделитель
отбрасывается) — снял второй предел: все прежние операции унарны и не
сопоставляли ЧАСТИ сетки. В богатой конфигурации training 36 → **44 (11.0 %)**,
evaluation 6 → **13 (3.2 %)** — охват eval удвоился за один слой: семь новых
задач вида «or_h ▸ paint[1]», «xor_v ▸ paint[6]» — наложение половин, где слой
отношений и переменная-цвет работают только ВМЕСТЕ. В чистом протоколе (без
переменных) eval не сдвинулся — честная иллюстрация композиционности механизмов.

С `--parametric` язык получает **переменную-цвет**, связываемую из палитры
конкретной задачи (`keep[c]` / `drop[c]` / `paint[c]`): training 22 → **23**
(5.8 %) — добавилась задача a740d043 «drop[1] ▸ bbox»; на evaluation базовый
замер не изменился — честный результат: цветовой фильтрации там мало на
достижимой глубине.

С `--objects` добавляется **переменная-объект** (`each[f]` — применить f к
каждому связному объекту, `pick[k]` — k-й по размеру, и предикатные семейства
`big[f]` / `small[f]` / `one[f]` — «самому большому / маленькому / всем
одиночкам»; каждое семейство — в двух СВЯЗНОСТЯХ: обычной цветослепой и
одноцветной с суффиксом `c`, где объект — область одного цвета):
evaluation 4 → **5** базовым замером — задача 8ee62060 взята
программой «flip_h ▸ each[flip_h]» («отрази сетку, затем отрази каждый объект
на месте»: позиции зеркалятся, ориентация объектов сохраняется); training
23 → **25 (6.2 %)** — предикаты взяли aedd82e4 «one[paint[1]]» и 67385a82
«paint[8] ▸ one[paint[3]]», а переобучившуюся «paint[1] ▸ small[paint[2]]»
(b230c067) скрытый тест честно отсеял. Вместе с ростом библиотеки из training:
evaluation **7 (1.8 %)**. Полная траектория охвата за счёт переменных и опыта:
eval 4 → 5 → 7, training 22 → 23 → 25.

Честный нулевой результат: одноцветная связность (`onec`/`bigc`/…) на глубине ≤2
охвата НЕ добавила (числа те же), стоимость поиска ×2, зато скрытый тест отсеял
ещё одно переобучение (d9fac9be «pickc[3] ▸ bbox»). Механизм оставлен: язык
богаче, выигрыш ожидается на большей глубине/с другими действиями.

С `--deep BUDGET` включается **умный поиск глубины 3** по нерешённым задачам
(`reasoning/deep_search.py`): биграммный приор «какой шаг вероятен ПОСЛЕ какого»
учится из training-решений и СГЛАЖИВАЕТСЯ смесью с равномерным распределением
(P = 0.9·P_биграмм + 0.1/V): стоимость любого шага ограничена, и накопленный
опыт не может вытеснить путь за границу бюджета (урок и замер чувствительности —
AUDIT, дополнения 11–12). Направляющая эвристика раньше разворачивает узлы,
чьи промежуточные сетки ближе к целевой (переупорядочивание без отсечения).
Результат (бюджет 20000/задачу ≈ 2.7 % полного перебора глубины 3): evaluation
**+3 задачи глубины 3** — 0c786b71 и 833dafe3 сырой композицией
«flip_h ▸ flip_v ▸ mirror_quad» (то же, что открывает путь знания — два
независимых механизма сходятся) и 59341089 «flip_h ▸ mirror_h ▸ tile_h»,
которой нужно ~13 тыс. проверок при ЛЮБОМ сглаживании — бюджет поднят по
замеренной потребности, не подгонкой. На training deep-стадия впервые дала
**+1 задачу глубины 3** — 6f8cd79b «color+1 ▸ paint[8] ▸ outline»
(переобучившаяся «xor_v ▸ bbox ▸ flip_v» по-прежнему честно отсеяна скрытым
тестом). Итог с deep: training **49 (12.2 %)**, evaluation **16 (4.0 %)**.

Язык СРЕДНЕГО УРОВНЯ в deep-стадии: рост библиотеки идёт ПЕРЕД глубоким
поиском, и абстракции training-решений (`flip_h∘flip_v`, `keep_largest∘bbox`)
участвуют в языке поиска — структуры глубины до 6 в базовых именах достижимы
на глубине 3 (у новых имён нет биграммных счётчиков — достижимость
гарантирует сглаживание; проверено юнит-тестом). Честный ноль: **+0 новых
задач** на обоих сплитах при пренебрежимой цене — нынешние абстракции
выросли из решений глубины ≤2, и нерешённые задачи в пределах бюджета
не являются их композициями; языку среднего уровня нужны разнообразные
ГЛУБОКИЕ решения как сырьё (AUDIT, дополнение 13).

Итеративный wake/sleep (`--deep-rounds N`): найденное в раунде становится
опытом следующего — со 2-го раунда пул = ВСЕ решения, прошедшие скрытые
тесты (оба сплита; скрытый тест текущей задачи в её поиске не участвует
никогда), из пула растут новые абстракции (`flip_v∘mirror_quad`,
`flip_h∘flip_v∘mirror_quad`) и пересчитывается приор. Раунд 2 нашёл НОВУЮ
задачу глубины 3 — f823c43c «restore_sym ▸ drop[6] ▸ fill_holes»:
evaluation **17 (4.2 %)**; раунд 3 честно сухой (насыщение при данном
языке и бюджете). Абляция атрибутирует выигрыш точно: с приором раунда 1
задача не находится НИ С КАКИМИ абстракциями, с пулом раунда 2 — находится
при ЛЮБОМ языке (~15.3 тыс. проверок). Итерация помогла через ПРИОР
(в eval-решениях restore_sym — частый первый шаг), а абстракции и здесь
дали ноль — согласуется с дополнением 13 (AUDIT, дополнение 15).

Потолок глубины — не ограничение: `--deep-depth 4` при том же бюджете
воспроизводит покрытие бит-в-бит (training 49, evaluation 17, все находки
глубины 3, ни одной глубины 4) — сглаживание и эвристика удерживают
порядок обхода, разрешённая глубина сама по себе ничего не даёт и ничего
не ломает. Ограничение сейчас — связка бюджет × приор: пути глубины 4
дороже по приору, и бюджет 20000 до них не доходит (AUDIT, дополнение 18).

Полная траектория за все шаги (скрытые тесты, честный протокол):
**training 22 → 25 → 36 → 44 → 48 → 49 (12.2 %), evaluation
4 → 7 → 9 → 16 → 15 → 16 → 17 (4.2 %)** — переменные (перечисляемые и
вычисляемые), знание из чтения/опыта, умный поиск, слои расширения и
отношений, итеративный wake/sleep. Провал 16 → 15 (сменившийся биграммный
приор вытеснил 59341089 за бюджет deep-стадии) был записан как минус и
исправлен ПРИНЦИПОМ, а не подгонкой: сглаживание ограничивает стоимость
любого шага, бюджет поднят по замеренной потребности (таблица
чувствительности — AUDIT, дополнение 12); вклад каждого механизма
измерен отдельно.

## Единый агент (Mind): чтение учебника измеримо улучшает решение ARC

Раньше способности жили в 50+ отдельных демо, а оркестратором была рука автора.
`thinking_system/mind/` — один постоянный агент, который:

- **сам маршрутизирует опыт трёх типов**: текст → читает; грид-задача → решает;
  мир-лабиринт → исследует (существующий ActingAgent: активный вывод
  прагматика/эпистемика, карта мира — таблица переходов);
- **переносит знание через границу доменов**: слова учебника заземляются в
  грид-примитивы индукцией из показов («отражение [[1,2],[3,4]] → [[2,1],[4,3]]»),
  определения («поворот это сначала отражение потом переворот») растят библиотеку;
- **думает дольше над трудным**: бюджет поиска эскалирует по лестнице
  глубина/бюджет, а не фиксирован; ступень глубины 3 идёт УМНЫМ поиском
  (сглаженный биграммный приор из собственных решений + эвристика близости
  к цели, `reasoning/deep_search.py`); честное «не решил» при исчерпании;
- **помнит между запусками**: библиотека, словарь, решения и нерешённое
  сохраняются в JSON и переживают процесс;
- **имеет повестку** (зачаток автотелии): сам возвращается к нерешённым задачам,
  когда его язык вырос, консолидирует повторяющиеся комбо своих решений и держит
  открытые ВОПРОСЫ — слова, которые встретил в определениях, но заземлить не смог;
- **вопросы — активные ЦЕЛИ**: текст, ПОКАЗЫВАЮЩИЙ слово из открытого вопроса,
  читается раньше более «ценных» (цель важнее любопытства); незавершённые
  определения не выбрасываются, а ждут в памяти и ДОСТРАИВАЮТСЯ, когда нужное
  слово заземлится из другого текста (цепочка знания через границы текстов);
- **сам выбирает, ЧТО читать**: библиотека текстов оценивается по эпистемической
  ценности (сколько новых слов заземлится и определений соберётся СЕЙЧАС) с
  переоценкой после каждого прочтения — куррикулум «базовый учебник → продвинутый»
  возникает из любопытства, а не задаётся скриптом; бесполезный текст честно
  пропускается («ничего выучить»);
- **пользуется переменными трёх видов**: аргумент-цвет параметрических примитивов
  связывается из палитры конкретной задачи (`keep[c]`/`drop[c]`/`paint[c]`) или
  ВЫЧИСЛЯЕТСЯ из входа (`keep[top]`/`drop[rare]` — самый частый/редкий цвет,
  `reasoning/parametric.py`); ОБЪЕКТ квантифицируется комбинатором `each[f]`
  («примени f к каждому связному объекту»), селектором `pick[k]` («k-й по
  размеру») и предикатами `big[f]`/`small[f]`/`one[f]` («самому большому /
  маленькому / одиночкам», `reasoning/object_param.py`); шаблоны с дыркой
  анти-унифицируются
  из накопленных решений (`reasoning/templates.py`: «keep[3] ▸ bbox» +
  «keep[2] ▸ bbox» → «? ▸ bbox») и пробуются после лестницы — структура
  глубины 3 по цене одного слота.

```bash
python run_mind.py            # полный evaluation-сплит ARC (~25 мин)
python run_mind.py --limit 60 # быстрый прогон
python run_mind_worlds.py     # третий тип опыта: текст + 10 свежих лабиринтов
```

Реальные числа полного прогона (400 задач evaluation, скрытые test-входы;
библиотека из ПЯТИ текстов в перемешанном порядке — порядок чтения агент
выбирает сам): базовый учебник (ценность 5) → продвинутый (2; поднимает
вопрос «что такое „обращение“») → «Словарь редких операций» (ценность
всего 1, но выбран РАДИ ВОПРОСА раньше более ценного текста — цель важнее
любопытства; вопрос закрыт показом, ждавшее определение «инверсии»
достроено в поворот на 90° `transpose∘flip_h`) → дополнительные операции
(2) → заметки без операций пропущены. Вопросов в повестке не осталось.

| этап жизни агента | верно на скрытых test |
|---|---|
| до чтения (seed + переменные) | 13 — в т.ч. семь наложений «or_h/xor_v ▸ paint[c]» |
| после САМОСТОЯТЕЛЬНО выбранного чтения библиотеки + возврат к нерешённому | **15** |

Обе новые задачи (0c786b71, 833dafe3) решены операцией «поворот на 180°»,
которая пришла ИЗ ТЕКСТА — тот же выигрыш, что рост библиотеки из опыта решений
(`run_arc.py`), но знание получено чтением. Честный ноль: добытый по цели
поворот на 90° новых eval-задач на глубине ≤2 не добавил (закрытие цели
показано, выигрыша на ARC у него пока нет). Стоимость размышления падает
по мере жизни; вторая сессия процесса решает задачи сразу — память
пережила запуск.

Третий тип опыта — МИРЫ (`run_mind_worlds.py`): агент получает вперемешку
текст и 10 свежих лабиринтов из случайного распределения и маршрутизирует
каждый опыт сам. Решённость проверяется исполнением маршрута в среде;
исследование останавливается, как только карта связала цель. ПЕРЕНОС МЕЖДУ
МИРАМИ живёт в жизни агента: решённые миры — тренажёр кросс-мирового навыка
(механизм `run_transfer`: линейная Q над RBF-тайлами, домен-рандомизация по
потоку жизни), причём подцель навыка агент ВЫУЧИВАЕТ из жизни — это цель
его прежних миров. Каскад виден внутри одной жизни: первые пять миров
беглым взглядом не решаются и уходят в ПОВЕСТКУ, после первого решения
навык начинает тренироваться — и следующие миры берутся беглым взглядом за
43–93 шага исследования; вернувшись по повестке, агент доходит в **10/10
(×1.05 от истинного оптимума — цена ранней остановки исследования)**.
Перенос измерен абляцией на 10 НОВЫХ свежих мирах: с навыком беглого
взгляда хватает в **9/10 (595 шагов исследования), с нуля — 3/10 (1568)**.
Карты миров и навык переживают процесс (сессия 2: исследовано 0). Честно:
подцель навыка одна (цель прежних миров) — миры чужой цели/размера навык
пропускает; лабиринты игрушечные (7×7, полная наблюдаемость).

Словарь ЧАСТИЧНО открыт (`mind/lexicon.py`): формы слова сводятся к основе
(стеммер `language/morphology` + префиксное сшивание основ), поэтому
определения в учебнике написаны естественными падежами («поворот это после
отражения ещё и переворот» — «отражения» узнаётся как форма выученного
«отражение»), а показ читается и из свободной прозы: строка с РОВНО двумя
сетками понимается как «вход → выход» («Например, отражение превращает
[[5, 0, 6]] в [[6, 0, 5]].»). Честные границы: снимается только
словоизменение (не словообразование), проза — на уровне строк-предложений,
и сами тексты — по-прежнему контролируемые учебники; выбор чтения — жадный
по ценности, без планирования наперёд. Шаблонам с дыркой нужны РАЗНООБРАЗНЫЕ
глубокие решения — при нынешнем опыте они ещё не дают новых задач;
механизм проверен тестами и включён в жизнь агента.

### Структура

```
thinking_system/
  encoders/    — сенсорный ингест (random-projection; шов под JEPA-энкодер)
  predictors/  — предиктор: MLP (шаг 1) + ансамбль для оценки неопределённости
  memory/      — эпизодическая память (кольцевой буфер + replay)
  streams/     — домен-агностичный пассивный поток (шаг 1)
  envs/        — управляемая среда: action→obs, мультиканальная (шаг 2)
  policies/    — выбор действия: active inference (любопытство) + baseline
  tasks/       — последовательность различных задач/режимов (шаг 3)
  consolidation/ — непрерывное обучение через replay, CLS (шаг 3)
  text/        — ингест книг (PDF/MD/код), словарь (байты/символы), датасет
  predictors/  — …+ SymbolicPredictor (следующий символ/байт) для текста
  metrics/     — ошибка, метрики любопытства, continual-learning (ACC/BWT/FWT)
  core/        — Experience, PredictiveLoop, ActiveInferenceLoop
  agent/       — CognitiveAgent (единый контур), ActingAgent, BeliefAgent (POMDP),
                 Q-опции, перенос, lifelong, unified/mega
  world/       — GridWorld, LatentWorldModel (JEPA), PartialGridWorld (POMDP),
                 распределение лабиринтов (maze_dist)
  language/    — грунтинг команд, определения, морфология, условные правила, планнер
  reasoning/   — индукция программ, рост DSL-библиотеки, ARC (arc_data), причинность
  mind/        — ЕДИНЫЙ агент: маршрутизация опыта, лексикон текст→сетки, память
books/         — сюда кладутся книги (PDF/MD) для обучения
run_mvp/step2/step3.py   — демонстрации шагов 1–3
run_book.py              — обучение по реальным книгам (held-out BPC)
run_agent.py             — единый когнитивный контур
run_arc.py               — честный замер на реальном ARC-AGI-1
run_mind.py              — единый агент: чтение учебника → выигрыш на ARC
run_mind_worlds.py       — единый агент: третий тип опыта (миры-лабиринты)
run_world/latent_world/partial/language.py — действие в мире и его расширения
show_learned/show_code/use_learned.py — что выучила и как использует модель
tests/                   — тесты (202, см. CI)
```

Ядро (шаги 1–3, текст) построено на абстрактных интерфейсах (ABC) — компоненты
взаимозаменяемы; поздние слои (reasoning/, agent/, language/) — конкретные классы
без интерфейсов (техдолг, см. AUDIT.md). «Швы» под следующее: generative replay,
дискретный active inference (pymdp / RxInfer), GPU/torch-бэкенд тем же интерфейсом.

## Статус

Работают и воспроизводятся запуском: шаги 1–3 (предсказание / любопытство /
консолидация), обучение по **реальным данным** (книги на байтах), **единый
когнитивный контур**, **действие во внешнем мире** (модель мира, JEPA, POMDP,
язык → цель), **иерархический RL** (Q-опции, перенос между мирами, открытие
подцелей), **рассуждение** (индукция программ, причинность, рост DSL),
**честный замер на реальном ARC-AGI-1** и **единый постоянный агент** (Mind:
чтение → измеримый выигрыш на ARC, память между запусками, повестка).
212 тестов + smoke-прогоны демо в CI.

Это инженерный синтез из проверенных по отдельности компонентов на чистом numpy
(torch — опционально для масштаба), без LLM. Все среды и корпуса — игрушечного
масштаба; что подтверждено, что было завышено и что исправлено — в
[AUDIT.md](AUDIT.md).

По операциональным критериям «думающей системы»: (1) один агент сам выбирает
способ решения — есть на трёх типах опыта (текст/сетки/миры); (2) знание из одного
представления улучшает другое — показано (текст → +2 задачи ARC на скрытых
тестах); (3) результат растёт между запусками — показано (состояние на диске,
645→26 программ поиска); (4) задачи не порождены собственными примитивами —
реальный ARC. Всё — на игрушечном масштабе, словарь открыт лишь частично
(формы слов и проза-показы — да, произвольные тексты — нет): это первый
интегрированный шаг, а не «система думает». Переменные в языке есть в трёх
видах (цвет из палитры или вычисленный из входа; объект через each/pick,
предикаты big/small/one и две связности; шаблон-дырка из анти-унификации);
умный поиск глубины 3 работает (сглаженные биграммы опыта + эвристика цели:
+4 задачи eval и +1 training чистым поиском, включая одну из итеративного
wake/sleep, конвергентно с путём знания). ЧТО читать, агент выбирает сам
(эпистемическая ценность, честный пропуск бесполезного, открытые вопросы
в повестке). Граница сейчас измерена прямо (дополнения 13 и 15 AUDIT):
итерация «найденное → опыт» работает, но её выигрыш течёт через ПРИОР;
абстракции из решений глубины ≤2 дважды дали ноль — языку среднего уровня
нужен пул разнообразных ГЛУБОКИХ решений, а он насыщается за 2 раунда при
нынешнем языке и бюджете. Миры вошли в маршрутизатор третьим типом
опыта (беглый взгляд → повестка → долгое исследование → 10/10 свежих
лабиринтов, карты переживают процесс), и перенос МЕЖДУ мирами встроен в
жизнь: решённые миры тренируют кросс-мировой навык с выученной из жизни
подцелью, беглого взгляда на новых мирах хватает в 9/10 против 3/10 с
нуля. Из концептуального — полностью открытый словарь (словообразование,
связный текст за пределами строки-предложения), байтовые потоки в
маршрутизаторе, знание, текущее и В домен миров (сейчас текст помогает
только сеткам).
